# Сухопутные клетки: полный разбор проблем геометрии и план новой генерации

## 1. Текущее состояние

Таблица размеров клеток и региональные коэффициенты в целом получились удачными.

Она правильно отвечает на вопрос:

```text
сколько клеток должно быть внутри конкретной провинции
```

Однако текущий алгоритм геометрии отвечает на другой вопрос слишком примитивно:

```text
как механически разделить полигон провинции на N частей
```

Из-за этого итоговая карта выглядит не как естественные локальные территории, а как сглаженная Voronoi-нарезка.

Главный вывод:

```text
систему расчёта количества клеток сохраняем;
алгоритм построения геометрии нужно заменить.
```

---

# 2. Что именно не так с текущим результатом

## 2.1. Провинции выглядят как мини-Voronoi

Практически в каждой провинции повторяется один и тот же шаблон:

```text
несколько seed-точек
→ линии расходятся веером
→ появляется центральный Y-образный узел
→ территория делится на приблизительно равные сектора
```

Это создаёт эффект:

```text
разбитого стекла;
трещин;
паучьей сети;
механической нарезки.
```

Границы стали криволинейными, но не стали географически осмысленными.

## 2.2. Слишком много центральных узлов

У генератора заметна склонность сводить несколько внутренних границ в одну центральную точку:

```text
       |
       |
───────●──────
      / \
```

Тройное пересечение само по себе допустимо.

Проблема возникает, когда такой узел становится основным способом деления почти каждой провинции.

Для четырёх клеток сейчас часто получается:

```text
четыре области вокруг общего центра
```

Естественнее:

```text
сначала городская клетка;
потом отделение полуострова или долины;
потом деление оставшейся крупной территории.
```

То есть нужны последовательные осмысленные разрезы, а не одновременный рост всех частей.

## 2.3. Все провинции имеют одинаковый геометрический почерк

Несмотря на разные размеры и количество клеток, форма деления повторяется:

- клетки стремятся к похожей площади;
- линии имеют одинаковую плавность;
- регулярно возникают Y-узлы;
- линии одинаково изгибаются;
- прибрежные и внутренние провинции делятся почти одинаково;
- горные, равнинные и полуостровные территории выглядят одинаково.

В результате:

```text
Галисия;
Каталония;
Кастилия;
степная провинция;
горная провинция;
```

получают похожую внутреннюю геометрию.

Это неправильно.

## 2.4. Городская клетка не является основой деления

Сейчас логика визуально выглядит так:

```text
поставить N seed-точек
→ разделить провинцию
→ определить, в какой клетке оказался город
```

Правильная логика должна быть обратной:

```text
город
→ клетка вокруг города
→ оставшаяся территория
→ остальные клетки
```

Городская клетка должна создаваться первой.

## 2.5. Сглаживание не исправляет случайный маршрут границы

Важно различать:

```text
плавная линия ≠ естественная граница
```

Естественность определяется не количеством изгибов, а тем:

- что линия отделяет;
- где она начинается;
- где заканчивается;
- проходит ли по шейке;
- учитывает ли долину;
- учитывает ли рельеф;
- не режет ли полуостров;
- не проходит ли рядом с городом.

Добавление ещё большего шума или сглаживания только создаст более красивые случайные трещины.

---

# 3. Главная архитектурная ошибка

Текущий подход, судя по результату, близок к:

```text
N центров
→ одновременный рост N областей
→ выравнивание площадей
→ сглаживание
```

Такой алгоритм почти неизбежно создаёт:

- лепестки;
- центральные узлы;
- равномерные сектора;
- одинаковый почерк по всему миру;
- механическое ощущение.

Для нашего проекта нужен другой принцип:

```text
городская территория
+
последовательные естественные разрезы провинции
```

То есть вместо одновременного выращивания четырёх клеток нужно провести три лучших естественных разреза.

---

# 4. Что сохраняем без изменений

Система расчёта числа клеток остаётся.

Она отвечает только на вопрос:

```text
сколько клеток должно быть внутри провинции
```

Примеры:

```text
Ла-Корунья → 4 клетки
Большой Лондон → минимум 4–5 клеток
крупная сибирская провинция → несколько огромных клеток
```

Региональные коэффициенты и целевые площади не нужно переделывать.

Меняется только геометрический генератор.

---

# 5. Новая архитектура генерации

## Общая схема

```text
провинция
→ перевод в локальную метрическую проекцию
→ анализ формы
→ поиск города и географических якорей
→ построение городской клетки
→ генерация кандидатов на разрезы
→ оценка кандидатов
→ рекурсивное последовательное деление
→ обработка общих рёбер
→ валидация
```

---

# 6. Перевод провинции в локальную проекцию

Каждую провинцию нужно анализировать не в мировых пикселях Web Mercator, а в локальной метрической системе координат.

Это необходимо для корректного расчёта:

- расстояний;
- площади;
- длины границ;
- ширины перешейков;
- расстояния города до границы;
- компактности;
- длины полуостровов;
- ширины долин.

Web Mercator искажает масштаб по широте, поэтому нельзя использовать один мировой пиксельный порог для Испании, Сибири и Скандинавии.

Практически:

```text
малые и средние провинции:
локальная Azimuthal Equidistant или UTM

очень крупные провинции:
локальная равноплощадная проекция
```

# 7. Анализ формы провинции

До построения клеток генератор должен понять силуэт территории.

## 7.1. Вогнутые участки

Вогнутости часто показывают:

- основание полуострова;
- вход в бухту;
- переход между лопастями провинции;
- естественное место разреза.

Нужно находить:

```text
значимые concave vertices;
пары вогнутостей;
локальные шейки;
места резкого сужения полигона.
```

## 7.2. Медиальный скелет

Медиальный скелет полигона показывает:

- основные оси территории;
- ответвления;
- длинные полуострова;
- узкие коридоры;
- отдельные лопасти;
- потенциальные центры подзон.

Это один из главных инструментов анализа естественной формы.

## 7.3. Перешейки

Перешеек считается хорошим местом разреза, если:

```text
короткая линия
разделяет провинцию
на две достаточно крупные и связные части
```

Хороший пример:

```text
длина разреза: 20–30 км
части: 3000 и 5000 км²
```

Плохой пример:

```text
длина разреза: 15 км
одна часть: 40 км²
```

Во втором случае это просто мелкий хвост, а не самостоятельная территория.

## 7.4. Географические лопасти

Лопасть или полуостров становится отдельной кандидатной территорией, если:

- имеет достаточную площадь;
- связан узкой шейкой;
- имеет собственный устойчивый центр;
- отличается направлением основной оси;
- не является мелким береговым выступом.

## 7.5. Компактность и вытянутость

Нужно заранее измерять:

```text
compactness;
aspect_ratio;
minimum_width;
skeleton_branch_length;
perimeter_to_area_ratio;
```

Это пригодится и для генерации, и для валидации.

# 8. Городская клетка создаётся первой

## 8.1. Главное правило

```text
городская клетка не является случайным результатом деления;
она является первым обязательным объектом генерации.
```

Город должен находиться примерно по центру своей клетки.

Но это не означает геометрический центроид.

Для прибрежного города правильнее:

```text
город далеко от внутренних границ;
у города есть нормальное сухопутное пространство;
портовый берег входит в клетку;
клетка не становится узкой полосой вдоль моря.
```

## 8.2. Защитная зона города

Внутренним границам запрещено проходить слишком близко к городу.

Эквивалентный радиус целевой клетки:

```text
R = sqrt(target_area / π)
```

Для Галисии при цели 2100 км²:

```text
R ≈ 25,9 км
```

Начальный ориентир защитного радиуса:

```text
0.25–0.35 × R
```

То есть примерно:

```text
7–10 км
```

Это стартовое значение для калибровки.

## 8.3. Городская клетка не должна быть кругом

Она растёт по полю стоимости.

Проще расширяться:

- по равнинам;
- по долинам;
- вдоль естественной городской округи;
- к гавани;
- по связному hinterland.

Сложнее:

- через горный хребет;
- через большую реку;
- через узкий перешеек;
- в отдельный полуостров;
- через изолированную природную область.

## 8.4. Городская клетка не обязана быть крупнейшей

Допустимо:

```text
городская клетка = 1700 км²
соседняя сельская = 2400 км²
```

Если городская клетка имеет естественную форму.

Нельзя выравнивать все клетки до почти одинаковой площади ценой плохих границ.

---

# 9. Последовательное деление остатка

## Старый принцип

```text
4 seed-точки
→ одновременный рост
→ 4 лепестка
```

## Новый принцип

```text
1. Построить городскую клетку.
2. Получить остаток провинции.
3. Найти лучший естественный разрез остатка.
4. Разделить его.
5. Выбрать крупнейшую или наиболее сложную оставшуюся часть.
6. Повторять до нужного числа клеток.
```

Это рекурсивное бинарное разбиение.

---

# 10. Пример Ла-Коруньи

Для четырёх клеток логика может быть такой:

```text
1. Городская клетка вокруг Ла-Коруньи.
2. Отдельная западная прибрежная или полуостровная зона.
3. Южная внутренняя территория.
4. Восточная внутренняя территория.
```

Порядок:

```text
городская клетка
→ отделение выраженной прибрежной лопасти по шейке
→ деление оставшейся внутренней части
```

Такой результат будет выглядеть как четыре разные территории, а не как четыре сектора вокруг одной точки.

# 11. Каталог кандидатов на границы

Генератор не должен разрешать линии проходить где угодно.

Сначала строится набор допустимых разрезов.

## 11.1. Разрез через перешеек

Соединяет две близкие части внешней границы.

Преимущества:

- короткий;
- понятный;
- отделяет целую географическую лопасть;
- визуально естественный.

## 11.2. Разрез по хребту или водоразделу

Граница может идти вдоль:

- горного гребня;
- водораздела;
- края плато;
- линии между долинами.

Может начинаться у внешней границы и заканчиваться:

- у другой внешней границы;
- у реки;
- у существующей внутренней границы;
- у естественного узла.

## 11.3. Разрез по крупной реке

Не каждая река становится границей.

Подходит река, которая:

- достаточно крупная;
- делит провинцию на значимые части;
- не проходит через городской центр;
- имеет длинный непрерывный участок;
- не создаёт клетку-щель.

## 11.4. Разрез между двумя вогнутостями

Геометрический способ отделить одну лопасть от другой.

Используется, когда природные данные отсутствуют или не дают надёжной линии.

## 11.5. Разрез от природного барьера до внешней границы

Примеры:

```text
хребет → река;
река → берег;
перевал → внешняя граница;
граница долины → берег.
```

## 11.6. Геометрический fallback

Для большой компактной равнины природного барьера может не быть.

Тогда разрешён искусственный разрез, но он должен:

- быть относительно коротким;
- не проходить рядом с городом;
- не создавать узкие клетки;
- не повторять центральный веер;
- не быть идеальной прямой;
- не разрезать полуостров случайно.

# 12. Оценка кандидатов

Каждый кандидат получает итоговый score.

```text
cut_score =
    natural_barrier_score
  + isthmus_score
  + area_balance_score
  + compactness_improvement
  + geographic_identity_score
  + city_safety_score
  - sliver_penalty
  - peninsula_damage_penalty
  - excessive_length_penalty
  - thin_corridor_penalty
  - radial_pattern_penalty
```

## Главный приоритет

```text
1. Географический смысл.
2. Нормальная форма клеток.
3. Безопасность городской клетки.
4. Площадь.
```

Баланс площади не должен доминировать.

---

# 13. Штрафы

## 13.1. Проход рядом с городом

```text
граница ближе защитного радиуса
→ кандидат почти всегда отклоняется
```

## 13.2. Разрезание полуострова вне шейки

```text
граница пересекает длинный полуостров случайно
→ очень большой штраф
```

## 13.3. Создание клетки-щели

```text
минимальная локальная ширина слишком мала
→ кандидат отклоняется
```

## 13.4. Острый хвост

```text
клетка получает длинный узкий выступ
→ большой штраф
```

## 13.5. Слишком длинная граница

Короткая естественная линия предпочтительнее длинной извилистой, если обе дают похожие территории.

## 13.6. Радиальный шаблон

Если новый разрез создаёт очередной центральный веер:

```text
radial_pattern_penalty
```

должен существенно снижать оценку.

---

# 14. Правила внутренних узлов

## 14.1. Центральные звёзды не должны быть стандартом

Для обычной провинции:

```text
3 клетки:
необязательно один Y-узел;

4 клетки:
не должен автоматически появляться узел степени 4;

5 клеток:
не должно быть пяти лепестков вокруг центра.
```

## 14.2. Ограничение на тройные узлы

Для провинций до четырёх клеток:

```text
не более одного внутреннего тройного узла
```

Но предпочтительно строить последовательные границы без общего центрального узла.

## 14.3. Крестовина запрещена

```text
    |
────●────
    |
```

Такой узел почти всегда выглядит искусственно.

---

# 15. Правила формы линий

## 15.1. Нельзя добавлять равномерный шум

Плохой метод:

```text
прямая
→ случайное смещение каждой точки
→ декоративная змея
```

## 15.2. Нужны крупные, а не мелкие изменения направления

Хорошая граница:

- имеет 2–5 крупных поворотов;
- местами почти прямая;
- местами изгибается;
- имеет разную кривизну;
- меняет характер в зависимости от причины границы.

## 15.3. Разный стиль по типу границы

| Тип основания | Характер линии |
|---|---|
| Река | Более извилистая |
| Водораздел | Длинные спокойные изгибы |
| Горный хребет | Крупная угловатая ломаная |
| Перешеек | Короткая поперечная линия |
| Равнина | Умеренно плавная |
| Городская округа | Мягкая обволакивающая форма |

---

# 16. Правила полуостровов

## Маленький полуостров

```text
целиком входит в одну клетку
```

## Средний полуостров

```text
отделяется по естественной шейке
```

## Очень большой полуостров

```text
сначала отделяется от основной территории,
затем при необходимости делится внутри себя
```

Запрещено:

```text
войти границей с одного берега;
случайно пересечь полуостров;
выйти с другого берега вне шейки.
```

---

# 17. Правила побережья

Каждая нормальная прибрежная клетка должна иметь:

```text
значимый участок берега
+
нормальный внутренний hinterland
```

Нельзя создавать:

- узкие полосы вдоль моря;
- прибрежные клинья;
- клетки с длинным берегом и почти отсутствующей сушей;
- несколько клеток внутри одной маленькой бухты;
- две границы, упирающиеся в берег почти рядом.

Исключения:

- естественная узкая прибрежная долина;
- коса;
- остров;
- узкий полуостров.

---

# 18. Правила площади

Количество клеток определяет таблица.

Но после выбора естественной геометрии допустим разброс площадей.

## Обычные регионы

```text
0.55–1.65 от target_cell_area
```

## Редкие и фронтирные регионы

```text
0.40–2.20 от target_cell_area
```

## Отношение площадей соседей

```text
обычный регион: не больше 3 раз;
редкий регион: не больше 5 раз.
```

Географически логичная разница важнее математического равенства.

# 19. Валидатор

## 19.1. Топология

Проверять:

```text
каждая клетка связна;
нет перекрытий;
нет дыр;
сумма площадей клеток равна площади провинции;
общие границы совпадают;
нет соседства только точкой;
нет MultiPolygon без специального разрешения.
```

## 19.2. Город

Проверять:

```text
город находится внутри назначенной клетки;
город не прижат к внутренней границе;
городская клетка имеет нормальную площадь;
прибрежный город имеет логичный берег;
городская клетка не имеет длинного хвоста.
```

## 19.3. Форма

Проверять:

```text
compactness;
aspect_ratio;
minimum_width;
perimeter_to_area_ratio;
длину острых хвостов;
длину внутренних границ;
число тройных узлов;
число радиальных узлов;
```

## 19.4. География

Проверять:

```text
не разрезан ли полуостров вне шейки;
не разделена ли одна долина случайно;
не создана ли прибрежная полоска;
не отделён ли микроскопический хвост;
не проходит ли граница через городскую защитную зону.
```

# 20. Почему нельзя сразу запускать весь мир

Текущий скриншот показывает, что массовый прогон был сделан до проверки базовых географических архетипов.

# 21. Диагностический режим генератора

До массовой генерации скрипт должен уметь рисовать debug-карту одной провинции.

Обязательные диагностические слои:


# 23. Что оставить от Voronoi и watershed

Эти методы можно оставить только как вспомогательные.

Допустимые применения:

```text
первичная расстановка центров;
fallback для пустой равнины;
черновая оценка зон притяжения;
предварительная гипотеза;
```

Нельзя использовать их как окончательный источник геометрии.

# 24. План разработки

## Этап 1. Остановить массовый финальный вывод

Сохранить:

- таблицу;
- количество клеток;
- площади;
- региональные профили.

Отключить:

- финальную мировую геометрию текущего алгоритма.

## Этап 2. Ла-Корунья как первый эталон

Сделать полный debug-режим.

Нужно получить:

- городскую клетку;
- полуостровную логику;
- три последовательных разреза;
- естественный итог.

## Этап 3. Отдельно реализовать city-first

Городская клетка считается готовой, когда:

- город не прижат к границе;
- клетка не круглая;
- есть логичный берег;
- нет длинного хвоста;
- форма соответствует окружению.

## Этап 4. Реализовать анализ формы

Добавить:

- skeleton;
- concavities;
- peninsula detector;
- isthmus detector;
- lobe segmentation.

## Этап 5. Реализовать каталог разрезов

Добавить:

- neck cuts;
- river cuts;
- ridge cuts;
- concavity cuts;
- fallback cuts.

## Этап 6. Реализовать scoring

Настроить веса так, чтобы:

```text
география > форма > город > площадь
```

## Этап 7. Реализовать recursive partition

Провинция делится последовательно.

Каждый новый разрез применяется только к одной части.

## Этап 8. Реализовать обработку общих рёбер

Общие рёбра хранятся один раз.

Нужно:

- snap;
- simplify;
- убрать дубли;
- не создавать щелей;
- не сглаживать каждую клетку независимо.

## Этап 9. Проверить 12 архетипов

До Иберии весь набор должен пройти визуально и геометрически.

## Этап 10. Запустить Иберию

После успешных архетипов:

```text
генерация всей Иберии;
автоматический отчёт;
ручной просмотр худших 5%;
настройка весов;
```

## Этап 11. Запустить мир

После стабильной Иберии:

```text
массовый прогон;
отбор худших 1–3%;
ручные overrides только для доказанных исключений;
```

# 25. Критерии готовности

Генератор готов, когда:

```text
нет массовых Y-узлов;
нет крестовин;
нет одинакового Voronoi-почерка;
городская клетка строится первой;
полуостровы режутся только по шейкам;
границы учитывают природные линии;
не менее 97% провинций не требуют ручного override;
нет дыр и перекрытий;
площади соответствуют региональным профилям;
визуально клетки читаются как естественные территории.
```

# 26. Итоговое решение

Текущую таблицу размеров сохраняем.

Текущую геометрию не дорабатываем косметически.

Необходимо заменить сам принцип:

```text
НЕ:
несколько seed-точек
→ одновременный рост
→ равные сглаженные сектора

А:
городская клетка
→ анализ формы провинции
→ каталог естественных разрезов
→ последовательное бинарное деление
→ обработка общих рёбер
→ строгая валидация
```

Главная цель:

```text
клетка должна восприниматься не как кусок полигона,
а как реальная локальная территория.
```
