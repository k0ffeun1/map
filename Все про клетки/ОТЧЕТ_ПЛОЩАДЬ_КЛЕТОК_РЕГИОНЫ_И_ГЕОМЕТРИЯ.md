# Сухопутные клетки: площадь, региональные правила и естественная геометрия

**Проект:** глобальная историческая стратегия на Godot 4  
**Репозиторий:** `k0ffeun1/map`  
**Статус документа:** архитектурный отчёт и план перед массовой генерацией сухопутных клеток

---

## 1. Главный вывод

Для мира нельзя использовать единый размер клетки и нельзя использовать одно правило «каждая провинция делится на четыре части».

Правильная система:

```text
региональный профиль
→ площадь конкретной провинции
→ локальная географическая сложность
→ городские и географические якоря
→ генерация естественной геометрии
```

Регион задаёт базовый **целевой размер клетки**, а провинция корректирует число клеток своей площадью, берегом, рельефом, формой и важными центрами.

Ла-Корунья, Большой Лондон и Красноярский край не должны иметь одинаковый размер клетки и одинаковый принцип деления.

## 2. Что найдено в текущем проекте

### 2.1. Территориальная лестница уже правильная

```text
Клетка
→ Провинция
→ Регион
→ Макрорегион
→ Суперрегион
→ Континент
→ Мир
```

Уровень `zone` удалён. Клетка должна хранить только непосредственного родителя — `province_id`.

### 2.2. Геометрия, паспорт и состояние разделены

Текущая архитектура уже отделяет:

```text
assets/map_geometry/provinces.json
assets/game_data/provinces.json
assets/game_data/regions.json
assets/scenarios/.../province_state.json
```

Это нужно сохранить. Площадь провинции является свойством постоянной геометрии и должна находиться в `map_geometry`.

### 2.3. Полная мировая система регионов пока отсутствует

На момент анализа:

- `assets/game_data/regions.json` содержит только две тестовые записи;
- `assets/game_data/macroregions.json` содержит только Иберию и Францию;
- у большинства провинций `region_id` ещё пустой;
- для Иберии есть отдельный генератор и ручная карта из 23 регионов.

Поэтому невозможно честно назвать существующую таблицу «точной таблицей всех регионов проекта»: сначала нужно закончить региональную таксономию.

В приложенной книге создан **проектный каталог из 273 региональных профилей v1**. Это не утверждение, что эти назначения уже записаны в репозиторий. Это детальная основа для заполнения `regions.json` и дальнейшей привязки провинций.

### 2.4. Площадь провинции пока не экспортируется

`build_provinces.py` уже умеет вычислять приблизительную площадь для фильтрации мелких частей. Однако после финальной очистки перекрытий в выходную запись записываются только:

```text
rings
bbox
name
id
```

Поля `area_km2` пока нет.

Это первая задача, потому что без окончательной площади нельзя корректно назначить число клеток.

## 3. Где именно считать площадь

Площадь нужно вычислять **после всех геометрических изменений**:

```text
исходный Admin1
→ слияния мелких единиц
→ удаление ненужных островов
→ crop
→ simplify
→ удаление перекрытий
→ расчёт area_km2
→ экспорт
```

Если вычислить площадь раньше `_remove_overlaps`, итоговые числа будут расходиться с реально используемой в игре геометрией.

Рекомендуемый метод:

```python
from pyproj import Geod
geod = Geod(ellps="WGS84")
```

Для каждого внешнего кольца берётся абсолютная геодезическая площадь; площади внутренних отверстий вычитаются. Нельзя считать площадь в пикселях Web Mercator и затем использовать один глобальный коэффициент: искажение зависит от широты.

Итоговая запись:

```json
{
  "id": "province:1234",
  "area_km2": 7950.2,
  "bbox": [],
  "rings": []
}
```

## 4. Почему не нужны ручные интервалы для каждого региона

Модель вида:

```text
Галисия:
0–5000 км² = 3 клетки
5000–10000 км² = 4 клетки
...
```

понятна визуально, но при сотнях регионов создаст тысячи вручную редактируемых порогов.

Надёжнее хранить:

```json
{
  "target_cell_area_km2": 2100,
  "min_cells_per_province": 1,
  "max_cells_per_province": 10
}
```

А диапазоны строить автоматически.

Порог, начиная с которого провинция получает `N` клеток:

```text
threshold(N) = (N - 0.5) × target_cell_area_km2
```

Для Галисии при цели `2100 км²`:

```text
менее 3150 км²     → 1 клетка
3150–5249 км²      → 2 клетки
5250–7349 км²      → 3 клетки
7350–9449 км²      → 4 клетки
9450–11549 км²     → 5 клеток
11550–13649 км²    → 6 клеток
```

Ла-Корунья площадью примерно `7950 км²` получает четыре клетки до дополнительных географических поправок.

## 6. Формула числа клеток

```text
K_local =
  coast_factor
  × relief_factor
  × shape_factor

K_local = clamp(K_local, 0.85, 1.35)

raw_count =
  province_area_km2
  / region.target_cell_area_km2
  × K_local

area_count = round(raw_count)

final_count =
  clamp(
    max(area_count, anchor_minimum, geography_minimum),
    region.min_cells_per_province,
    region.max_cells_per_province
  )
```

### Берег

```text
нет побережья                     1.00
обычное побережье                 1.05
бухты и полуострова               1.12
сильно изрезанный берег           1.20
архипелаг                         1.30
```

### Рельеф

```text
равнина                           1.00
смешанный рельеф                  1.05
холмы и долины                    1.10
горы и перевалы                   1.18
сложные горные бассейны           1.25
```

### Форма

```text
компактная                        1.00
вытянутая                         1.05
несколько выраженных лопастей     1.12
полуостровы и перешейки           1.18
```

Общий множитель ограничивается значением `1.35`, чтобы сложное побережье и рельеф не удваивали число клеток неконтролируемо.

## 8. Городская клетка

Городская клетка создаётся первой.

Жёсткие правила:

1. Город находится внутри центральной части клетки.
2. Граница не проходит вплотную к маркеру города.
3. Клетка естественно обволакивает город.
4. Городская клетка не обязана быть крупнейшей.
5. Прибрежный город получает логичный участок побережья.
6. Полуостров не разрезается поперёк вне естественного перешейка.
7. Крупная агломерация может повышать **минимальное число клеток**, но не обязана уменьшать все клетки региона.

Рекомендуемый контроль центральности:

```text
distance(city, nearest_cell_border)
>= 0.25 × equivalent_cell_radius
```

Для вытянутых прибрежных клеток дополнительно используется нормализованная дистанция внутри полигона, а не только расстояние до центроида.

## 9. Как получать естественные границы

Обычный Voronoi допустим только как начальная гипотеза. Финальная геометрия должна строиться через поле стоимости и рост областей.

### 9.1. Входные данные

```text
полигон провинции
городские точки
береговая линия
крупные реки
рельеф/склоны
гребни и водоразделы
дороги — только как слабые ориентиры, если они статичны для карты
```

### 9.2. Опорные точки

Порядок:

```text
1. главный город;
2. другие обязательные городские центры;
3. выраженный полуостров;
4. изолированная долина или бассейн;
5. остальные точки методом weighted farthest point.
```

### 9.3. Поле стоимости

Граница охотнее проходит по:

- водоразделам;
- хребтам;
- крупным рекам;
- перевалам;
- перешейкам;
- естественным сужениям;
- границам долин.

Граница получает штраф за:

- приближение к городу;
- разрезание полуострова вне шейки;
- создание тонкого коридора;
- длинный острый хвост;
- чрезмерную вытянутость;
- разрыв естественной долины.

### 9.4. Алгоритм

```text
1. Перевести провинцию во временный рабочий raster.
2. Создать city influence field.
3. Создать barrier/cost field.
4. Поставить обязательные anchors.
5. Добавить недостающие seeds.
6. Выполнить multi-source region growing или watershed.
7. Балансировать площади переносом пограничных пикселей.
8. Векторизовать области.
9. Собрать общие рёбра один раз.
10. Сгладить линии без нарушения топологии.
11. Запустить валидатор.
```

## 10. Валидатор

### Геометрия

```text
каждая клетка связна;
нет перекрытий;
нет дыр между клетками;
сумма площадей клеток равна площади провинции;
общие границы двух клеток совпадают;
нет соседства только через точку;
нет тонких коридоров;
нет длинных острых хвостов;
нет бессмысленного разрезания полуостровов;
```

### Город

```text
город находится внутри назначенной клетки;
город не прижат к границе;
городская клетка имеет допустимую площадь;
прибрежный город имеет логичный доступ к берегу;
```

### Площадь

```text
обычный регион:
0.55–1.65 от target

редкий/фронтирный регион:
0.40–2.20 от target

отношение площадей соседних клеток:
не более 3 в обычных регионах
не более 5 в редких регионах
```

Исключения разрешаются для:

- островов;
- узких речных долин;
- горных проходов;
- метропольных ядер;
- географически изолированных частей.

## 12. Как создать недостающие регионы мира

Историко-географический регион нельзя надёжно получить только кластеризацией полигонов.

Нужна гибридная схема:

```text
1. Ручная таксономия важных исторических областей.
2. Автоматическое создание кандидатов для непокрытых провинций.
3. Проверка связности и компактности.
4. Ручная корректировка названий и состава.
5. Фиксация стабильных region_id.
```

Автоматический кандидат учитывает:

- соседство провинций;
- общую площадь;
- компактность;
- горные и речные барьеры;
- побережья;
- близость исторических центров;
- современную страну только как вспомогательный сигнал.

Современная страна не является постоянным родителем региона.

В Excel-файле создан каталог из **273 проектных регионов/зон v1** для Европы, Азии, Африки, Америк и Океании. Его нужно превратить в реальный `regions.json` через явное сопоставление `province_id → region_id`.

## 13. План разработки

### Этап 1. Площади

- добавить `area_km2` после `_remove_overlaps`;
- сформировать CSV всех провинций;
- проверить площади MultiPolygon и отверстий;
- составить статистику по странам и будущим регионам.

### Этап 2. Региональная таксономия

- завершить Иберию;
- затем Францию, Британские острова, Италию, Низкие земли;
- пройти остальные макрорегионы;
- использовать автоматические fallback-кандидаты только для черновой группировки.

### Этап 3. Профили

- завести P0–P8;
- назначить каждому региону target/min/max;
- выполнить предпроход ожидаемого числа клеток;
- установить мировой бюджет.

### Этап 4. Геометрия

- city-first;
- peninsula/isthmus detector;
- cost field;
- region growing;
- баланс площадей;
- топологическое сглаживание.

### Этап 5. Массовая проверка

- построить мир;
- автоматически отобрать худшие 3%;
- вручную исправлять только доказанные исключения;
- документировать каждый override.

## 14. Критерий готовности

```text
100% провинций имеют area_km2;
100% провинций имеют region_id;
100% регионов имеют профиль генерации;
ожидаемое число клеток известно до построения геометрии;
не менее 97% провинций проходят без ручного override;
нет перекрытий и дыр;
городские клетки проходят проверку центральности;
все ручные исключения имеют reason.
```
