# Тест: Индия — клетки → игровые провинции

Цель теста — проверить новую архитектуру без уменьшения `target_cell_count`.

## Принцип

1. Сначала каждая индийская Admin-1 получает своё полное число игровых клеток из `world_province_cell_targets*`.
2. Даже если у Admin-1 целевых клеток 18, Stage-6 строит все 18.
3. После этого отдельный этап группирует **готовые целые клетки** в игровые провинции.
4. Геометрия клетки на этапе создания провинций никогда не режется и не перерисовывается.

## Текущая тестовая политика

- `1–7` клеток в исходной Admin-1 → одна игровая провинция;
- `8+` → исходная Admin-1 разбивается;
- желаемый размер игровой провинции — около `6` клеток;
- предпочтительный максимум — `7` клеток.

Пример:

```text
Uttar Pradesh
18 готовых клеток
        ↓
3 игровые провинции
≈ 6 + 6 + 6 клеток
```

Граница каждой новой провинции — это объединение внешних границ принадлежащих ей клеток.

## Один запуск

```powershell
python scripts/tools/run_india_game_province_test.py
```

Создаются:

- `assets/subdivision_stage6/india_test_subdivisions.json` — готовые клетки Индии;
- `reports/india_stage6_test.json` — отчёт Stage-6;
- `assets/game_data/india_game_provinces_test.json` — игровые провинции Индии;
- `reports/india_game_provinces_test.json` — отчёт группировки.

## Просмотр в Godot

После генерации открыть `Main.tscn` и запустить проект.

- `P` — показать/скрыть **все готовые клетки Индии**;
- ЛКМ по клетке при выключенном `O` — показать исходную Admin-1, id клетки и площадь;
- `O` — показать/скрыть **игровые провинции Индии**, собранные из этих клеток;
- ЛКМ по игровой провинции — показать исходную Admin-1 и число клеток внутри неё;
- `P + O` — показать оба слоя одновременно: тонкие тёмные границы клеток снизу и более заметные серые границы игровых провинций сверху.

Оба слоя тестовые, независимые и не заменяют основную карту.
