# Генерация хаотичных извилистых клеток внутри провинции

## Пример: Ла-Корунья

## 0. Главная идея

Нельзя сразу рисовать каждую клетку случайной кривой.  
Если генерировать полигоны независимо друг от друга, появятся:

- щели между соседними клетками;
- наложения полигонов;
- самопересечения;
- тонкие хвосты;
- сломанное соседство;
- визуально грязные границы.

Правильный порядок:

```text
контур провинции
→ точки будущих клеток
→ обычное разбиение Voronoi
→ обрезка по контуру провинции
→ исправление плохих форм
→ выделение общих границ
→ превращение прямых границ в извилистые
→ проверка геометрии
→ сохранение готовых клеток
→ запекание визуального слоя
```

Главное правило:

```text
Сначала создаются правильные клетки с прямыми границами.
Только после этого общие границы превращаются в хаотичные и извилистые.
```

Генерация должна выполняться один раз офлайн через Python.  
Godot в runtime только загружает готовые полигоны и отображает их.

---

# 1. Исходные данные

Для генерации нужен внешний полигон провинции:

```text
Провинция Ла-Корунья
```

Этот полигон является жёстким внешним ограничением.

Он включает:

- береговую линию;
- сухопутные границы с соседними провинциями;
- острова, относящиеся к провинции;
- внутренние вырезы, если они существуют.

Ни одна игровая клетка не должна выходить:

- в море;
- в соседнюю провинцию;
- за внешний контур Ла-Коруньи.

---

# 2. Определить количество клеток

Для первого рабочего теста:

```text
Ла-Корунья = 4 игровые клетки
```

Не следует сразу генерировать десятки клеток.

Сначала нужно добиться хорошего результата на четырёх клетках:

1. северо-западная часть и район города Ла-Корунья;
2. западное побережье;
3. южная часть;
4. восточная внутренняя часть.

Это не окончательные названия клеток.  
Это ориентиры для размещения их центров.

---

# 3. Разместить точки-центры клеток

Внутри провинции размещаются четыре точки.

Каждая точка станет центром будущей клетки.

Плохо:

```text
●       ●

●       ●
```

Такая ровная сетка создаст слишком правильные клетки.

Лучше:

```text
      ●

●                 ●

          ●
```

Точки должны:

- находиться внутри провинции;
- не располагаться слишком близко друг к другу;
- не стоять прямо на внешней границе;
- не образовывать идеальную линию;
- учитывать крупные города;
- учитывать побережье;
- учитывать важные природные зоны;
- учитывать порты, реки и будущие стратегические объекты.

Для Ла-Коруньи одну точку желательно закрепить возле города и порта.  
Остальные можно размещать с контролируемой случайностью.

---

# 4. Добавить контролируемую случайность

Каждая точка получает небольшое случайное смещение.

Например, западная точка может смещаться:

- немного севернее;
- немного южнее;
- ближе к берегу;
- немного вглубь территории.

Случайность должна быть ограниченной.

Плохо:

```text
Точка западной клетки случайно переместилась на восток провинции.
```

Хорошо:

```text
Точка остаётся в своей западной зоне,
но при генерации получает небольшое случайное положение.
```

Нужно использовать общий seed:

```text
world_seed = 12345
```

Это позволяет получить карту, которая:

- выглядит случайной;
- повторяется при новой генерации;
- не меняется при каждом запуске;
- может быть восстановлена по одному числу.

---

# 5. Построить обычный Voronoi

По точкам строится обычное Voronoi-разбиение.

Принцип:

```text
Каждая часть территории относится к ближайшей точке.
```

Условный результат:

```text
┌────────────┬────────────┐
│     A      │     D      │
│            │            │
├────────────┼────────────┤
│     B      │     C      │
│            │            │
└────────────┴────────────┘
```

В реальности формы будут менее правильными, потому что точки расположены хаотично.

Voronoi используется только как основа.

Его проблема:

```text
границы слишком прямые;
форма выглядит математической;
клетки выглядят искусственно.
```

Поэтому прямые границы позже будут заменены извилистыми.

---

# 6. Обрезать клетки контуром провинции

Voronoi создаёт полигоны, которые могут выходить за пределы Ла-Коруньи.

Каждый полигон нужно пересечь с внешним контуром:

```text
готовая клетка =
Voronoi-полигон
∩
полигон Ла-Коруньи
```

После этой операции клетки останутся только внутри провинции.

---

# 7. Исправить плохие формы до хаотизации

После обрезки могут появиться:

- узкие хвосты;
- маленькие обломки;
- острые треугольники;
- отдельные островки;
- очень тонкие коридоры;
- клетки с плохим центром;
- клетки, касающиеся только одной точкой.

Правила хорошей клетки:

```text
Клетка состоит из одного основного полигона.
Клетка не похожа на длинную щель.
У клетки есть нормальный центр.
Внутри есть место для иконки и армии.
Соседи имеют общую границу нормальной длины.
Клетка не пересекает саму себя.
```

Если форма плохая, лучше:

1. немного передвинуть seed-точку;
2. заново построить Voronoi;
3. повторно обрезать клетку;
4. проверить результат.

Исправлять плохую базовую геометрию хаотичными линиями нельзя.

---

# 8. Выделить общие границы клеток

После получения правильных полигонов нужно выделить внутренние общие рёбра:

```text
граница A–B
граница A–D
граница B–C
граница C–D
```

Очень важно:

```text
Граница между клетками A и B должна существовать как одна общая линия.
```

Нельзя делать так:

```text
Клетка A отдельно искажает свою сторону.
Клетка B отдельно искажает свою сторону.
```

Это создаст:

- щели;
- наложения;
- несовпадающие линии;
- визуальные артефакты.

Правильно:

```text
Одна общая линия A–B
используется одновременно клеткой A и клеткой B.
```

---

# 9. Превратить прямую границу в извилистую

Допустим, есть прямая граница:

```text
A ---------------- B
```

## 9.1. Найти середину

```text
A --------●-------- B
```

## 9.2. Сдвинуть середину поперёк линии

Точка должна смещаться не вдоль границы, а в сторону от неё.

```text
          ●
        /
A -----           ----- B
```

## 9.3. Разделить новые отрезки

Каждый новый участок снова делится пополам.

```text
A ----●------●------●---- B
```

Новые точки получают меньшие случайные смещения.

## 9.4. Повторить несколько раз

Рекомендуемая глубина:

```text
3–4 рекурсивных уровня
```

Результат:

```text
A ___/‾\____/‾‾\_/‾\___ B
```

Это называется рекурсивным смещением середины отрезка.

---

# 10. Ограничить силу извилистости

Случайное смещение не должно быть бесконечным.

Иначе граница может:

- пересечь соседнее ребро;
- выйти за пределы провинции;
- разделить клетку на две части;
- создать тонкий хвост;
- пересечь саму себя;
- испортить соседнюю клетку.

Для первого теста:

```text
Первый крупный изгиб:
5–8% среднего размера клетки.

Каждый следующий уровень:
примерно в 2 раза слабее предыдущего.
```

Пример:

```text
уровень 1 = 100% силы;
уровень 2 = 50%;
уровень 3 = 25%;
уровень 4 = 12.5%.
```

Главное визуальное правило:

```text
Граница должна иметь несколько крупных непредсказуемых изгибов
и более слабые мелкие отклонения.
```

Она не должна превращаться в мелкую зубчатую пилу.

---

# 11. Использовать стабильный seed для каждой границы

Каждой общей границе назначается собственный seed.

Пример:

```text
edge_seed =
world_seed
+ min(cell_a_id, cell_b_id)
+ max(cell_a_id, cell_b_id)
```

Важно всегда сортировать ID.

```text
A–B и B–A должны считаться одной и той же границей.
```

Это даёт:

- одинаковый результат при повторной генерации;
- полное совпадение границ соседних клеток;
- независимость разных границ друг от друга;
- возможность перегенерировать только один плохой участок.

---

# 12. Не искажать внешний контур вместе с внутренними границами

На первом этапе:

```text
Внешняя граница Ла-Коруньи = исходная реальная граница.
Внутренние границы клеток = искусственные хаотичные линии.
```

Береговую линию нельзя обрабатывать той же силой, что внутренние границы.

Иначе:

- суша полезет в море;
- появятся наложения;
- берег потеряет узнаваемую форму;
- соседние провинции перестанут совпадать.

Если внешний контур нужно стилизовать, это делается:

- отдельно;
- слабее;
- с отдельными ограничениями;
- одинаково для всех соседних территорий.

---

# 13. Слегка смягчить острые углы

После рекурсивного смещения могут появиться острые пики.

Плохо:

```text
____/\/\____
```

Лучше:

```text
___/‾\_/‾\___
```

Можно применять слабое сглаживание, но только к самым резким местам.

Нельзя сильно сглаживать весь полигон.

Сильное сглаживание:

- уничтожит хаотичность;
- сделает все границы одинаковыми;
- может создать щели;
- может сместить общую границу;
- может изменить соседство.

Правильно:

```text
убрать самые острые пики;
сохранить крупные изгибы;
не менять внешний смысл формы;
после сглаживания снова проверить совпадение соседей.
```

---

# 14. Автоматически проверить геометрию

После генерации всех границ запускается валидация.

## 14.1. Клетка должна быть единым объектом

Не должно быть:

```text
основная клетка + отдельный маленький кусок
```

## 14.2. Не должно быть самопересечений

Граница не должна создавать петли.

## 14.3. Не должно быть щелей

Между соседними клетками не должно оставаться пустого пространства.

## 14.4. Не должно быть наложений

Клетка A не должна заходить поверх клетки B.

## 14.5. Не должно быть слишком тонких коридоров

Нужно задать минимальную допустимую ширину.

## 14.6. Должен существовать внутренний центр

Центр должен находиться внутри клетки и подходить для:

- иконки;
- подписи;
- армии;
- ресурса;
- клика;
- выделения.

Для этого лучше использовать не обычный геометрический центроид, а:

```text
representative point / pole of inaccessibility
```

То есть точку, гарантированно находящуюся внутри полигона.

## 14.7. Соседство должно быть корректным

Клетки считаются соседями, если у них есть общая граница достаточной длины.

Касание одной точкой не должно давать возможность движения.

---

# 15. Перегенерировать только плохую границу

Если плохой оказалась граница A–B, не нужно менять всю провинцию.

Правильный порядок:

```text
1. Изменить seed границы A–B.
2. Уменьшить силу её изгиба.
3. Перегенерировать только эту линию.
4. Пересобрать полигоны A и B.
5. Повторно проверить обе клетки.
```

Это позволяет исправлять карту локально.

---

# 16. Добавить систему ручных исключений

Полностью автоматическая генерация не всегда даст идеальный результат.

Для важных мест нужен файл настроек и исключений.

Пример:

```yaml
la_coruna:
  cell_count: 4

  seed_offsets:
    cell_2:
      x: -0.08
      y: 0.02

  edge_overrides:
    cell_1__cell_3:
      amplitude: 0.55

    cell_2__cell_4:
      regenerate_seed: 3
```

Через такие настройки можно:

- сдвинуть центр клетки;
- уменьшить извилистость конкретной границы;
- увеличить клетку;
- изменить seed только одного ребра;
- запретить границе проходить через город;
- закрепить важную точку;
- задать обязательную связь между клетками.

Не нужно вручную перерисовывать весь полигон.

---

# 17. Учитывать города и важные объекты

Важные объекты должны влиять на генерацию.

Для Ла-Коруньи:

```text
город Ла-Корунья
порт
берег
важные дороги
реки
будущие ресурсные зоны
```

Правила:

- город не должен оказаться прямо на границе;
- порт должен находиться в одной понятной прибрежной клетке;
- важная дорога не должна бессмысленно пересекать границу много раз;
- крупная река может стать естественной границей;
- важная бухта может определять форму клетки;
- стратегический берег должен быть отдельной удобной зоной.

Случайность отвечает за внешний вид, но не должна уничтожать игровую логику.

---

# 18. Сохранить готовые клетки

Для каждой клетки нужно хранить:

```text
ID
ID провинции
полный полигон
центр
площадь
список соседей
общие границы
bbox
географические признаки
```

Пример:

```json
{
  "id": "la_coruna_cell_01",
  "province_id": "la_coruna",
  "center": [1240, 590],
  "area_km2": 1830,
  "neighbors": [
    "la_coruna_cell_02",
    "la_coruna_cell_04"
  ],
  "polygon": [],
  "bbox": [],
  "features": [
    "coast",
    "port_access"
  ]
}
```

Клетка является записью данных, а не отдельной тяжёлой Node2D в Godot.

---

# 19. Запечь визуальный слой

После утверждения геометрии создаются два результата.

## 19.1. Визуальный слой

Содержит:

- заливку клеток;
- внутренние границы;
- границу провинции;
- отладочные подписи при необходимости.

Он запекается в тайлы карты.

## 19.2. ID-карта

Каждая клетка получает уникальный цвет.

Пример:

```text
Клетка 1 = RGB(0, 0, 1)
Клетка 2 = RGB(0, 0, 2)
Клетка 3 = RGB(0, 0, 3)
Клетка 4 = RGB(0, 0, 4)
```

Определение клика:

```text
координата мыши
→ координата ID-карты
→ цвет пикселя
→ cell_id
```

ID-карта должна сохраняться без потерь:

```text
PNG lossless
```

Нельзя использовать JPG или lossy WebP.

---

# 20. Что делает Godot

Godot не должен:

- генерировать Voronoi при запуске;
- искривлять границы;
- исправлять геометрию;
- рассчитывать полигоны;
- создавать тысячи отдельных объектов клеток.

Godot должен:

```text
загрузить готовые данные;
показать запечённую карту;
определять клетку под курсором;
рисовать выделение;
показывать динамические оверлеи;
использовать граф соседства для движения.
```

---

# 21. Как должна выглядеть Ла-Корунья

Плохо:

```text
┌──────────┬──────────┐
│          │          │
├──────────┼──────────┤
│          │          │
└──────────┴──────────┘
```

Плохо:

```text
/\/\/\/\/\/\/\/\/\
```

Хорошо:

```text
          реальное побережье
     ____/‾‾\____
   /               \
  |   Клетка 1      \____
  |      ___/‾\           \
  | ____/       \ Клетка 4 |
  |/             \         |
  |\ Клетка 2     \___     |
  | \____       _/    \    |
  |      \_____/ Клетка 3  |
   \                     _/
    \___________________/
```

Хорошие границы:

- имеют крупные изгибы;
- не повторяют друг друга;
- не идут строго вертикально;
- не идут строго горизонтально;
- не превращаются в мелкую пилу;
- не создают узких хвостов;
- сохраняют удобную форму клеток;
- выглядят хаотичными, но остаются технически правильными.

---

# 22. Что нельзя делать

## 22.1. Нельзя рисовать полигоны независимо

Иначе общие границы не совпадут.

## 22.2. Нельзя добавлять шум каждой точке контура

Получится мелкая дрожащая линия.

## 22.3. Нельзя слишком сильно сглаживать результат

Сглаживание уничтожит непредсказуемость и может сломать стыки.

## 22.4. Нельзя генерировать карту в runtime

Генерация выполняется только офлайн.

## 22.5. Нельзя делать клетки полностью случайными

Города, реки, порты, дороги, перевалы и побережье должны влиять на форму.

## 22.6. Нельзя хаотизировать плохую базовую геометрию

Сначала клетка должна быть правильной, а потом красивой.

---

# 23. Минимальный первый прототип

Первый практический этап:

```text
1 провинция
4 клетки
1 внешний контур
4 seed-точки
Voronoi
4–6 общих внутренних рёбер
3 уровня рекурсивного смещения
автоматическая проверка
экспорт JSON
экспорт PNG
```

Для теста нужно выводить несколько отладочных изображений:


# 25. Итоговый алгоритм

```text
Берём внешний контур Ла-Коруньи
→ определяем 4 зоны размещения центров
→ ставим 4 контролируемо-случайные seed-точки
→ строим обычный Voronoi
→ обрезаем клетки внешним контуром
→ исправляем плохие формы
→ выделяем общие внутренние рёбра
→ назначаем каждому ребру стабильный seed
→ рекурсивно смещаем середины рёбер
→ уменьшаем амплитуду на каждом уровне
→ слегка убираем острые пики
→ пересобираем полигоны соседних клеток
→ проверяем щели, наложения и самопересечения
→ локально перегенерируем плохие рёбра
→ сохраняем полигоны, центры и соседство
→ создаём визуальные тайлы
→ создаём lossless ID-карту
→ Godot загружает готовый результат
```

# 26. Главный вывод

Хаотичность должна применяться не ко всей клетке целиком, а к общим рёбрам между уже правильно построенными клетками.

```text
Voronoi отвечает за правильное разделение территории.
Общие рёбра отвечают за отсутствие щелей.
Рекурсивное смещение отвечает за хаотичный вид.
Валидация отвечает за техническую правильность.
Ручные исключения отвечают за особенно важные регионы.
```

Для начала нужно довести до хорошего состояния только Ла-Корунью с четырьмя клетками.  
После этого тот же генератор можно масштабировать на остальные провинции мира.
