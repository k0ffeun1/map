# Площадь клеток, население, города и пороги освоения

## 0. Главная идея

В игре с картой из реальных областей клетки почти никогда не будут одинаковыми по площади.

```text
маленькая клетка Европы: 300–1000 км²
средняя клетка Испании / Франции: 1000–4000 км²
крупная клетка степи / пустыни / Сибири: 10 000–50 000 км²
```

Но клетка — это всё равно минимальная игровая ячейка. Внутри неё не должно быть дополнительных подклеток, которыми игрок управляет отдельно.

Поэтому площадь нужна не для деления клетки, а для расчёта:

```text
сколько земли физически занимает клетка;
сколько людей она может поддерживать;
сколько еды / сырья она может дать;
сколько времени нужно, чтобы пройти через неё;
насколько дорого её контролировать;
насколько сложно её развивать.
```

Главное правило:

```text
Площадь даёт масштаб.
Природа даёт пригодность.
Освоение даёт реальное использование.
Город даёт переработку, торговлю и городское население.
```

## 1. Важное исправление: не делить клетку внутри

Ранее был термин `habitable_share` — «какая часть клетки пригодна для жизни».

Для твоей игры это плохой термин, потому что он звучит так, будто клетка делится на внутренние части.

Так делать не надо.

Клетка остаётся одной минимальной ячейкой.

Вместо `habitable_share` лучше использовать:

```text
settlement_factor     // пригодность клетки для поселений
usable_land_factor    // общая полезность земли
livability_factor     // удобство жизни
```

Это не значит, что мы делим клетку на 20% и 80%.

Это значит:

```text
эта клетка как единое целое лучше или хуже подходит для жизни и хозяйства.
```

Пример:

```text
плодородная равнина: settlement_factor = 1.20
обычная равнина:     settlement_factor = 1.00
холмы:               settlement_factor = 0.75
горы:                settlement_factor = 0.25
тундра:              settlement_factor = 0.10
болото:              settlement_factor = 0.05
пустыня:             settlement_factor = 0.03
```

То есть тундровая клетка не делится на куски. Она просто имеет очень низкую пригодность для поселений.

## 2. Площадь клетки

У каждой клетки нужно хранить реальную площадь:

```text
area_km2
```

Но использовать её напрямую опасно.

Плохая формула:

```text
полезность = area_km2
```

Тогда огромная тундра автоматически станет полезнее маленькой плодородной европейской клетки.

Правильнее переводить площадь в игровой коэффициент с ограничением.

### 2.1 Area factor

```text
area_factor = sqrt(area_km2 / 1000)
area_factor = clamp(area_factor, 0.4, 4.0)
```

Где:

```text
1000 км² — условная базовая площадь клетки;
0.4 — минимум, чтобы маленькие клетки не были слишком слабыми;
4.0 — максимум, чтобы огромные клетки не ломали баланс.
```

Примеры:

```text
400 км²:
sqrt(400 / 1000) = 0.63
area_factor = 0.63

1000 км²:
sqrt(1000 / 1000) = 1.00
area_factor = 1.00

10 000 км²:
sqrt(10000 / 1000) = 3.16
area_factor = 3.16

25 000 км²:
sqrt(25000 / 1000) = 5.00
area_factor = 4.00 после ограничения
```

Главное:

```text
большая клетка получает бонус за размер,
но этот бонус не растёт бесконечно.
```

## 3. Регион задаёт базовую плотность, а не клетка

`base_density` лучше не хранить в каждой клетке.

Правильнее хранить его на уровне территории / региона.

Например:

```text
Region {
  id
  name

  base_rural_density      // базовая сельская плотность населения
  urbanization_factor     // склонность населения жить в городах
  prosperity              // богатство региона
  security                // безопасность региона
  technology_level        // технологии / аграрный уровень
  culture
  religion
}
```

Примеры:

```text
Галисия:              base_rural_density = 30–45 чел/км²
Кастилия:             base_rural_density = 15–30 чел/км²
Фландрия:             base_rural_density = 60–120 чел/км²
Северная Италия:      base_rural_density = 50–100 чел/км²
Степная окраина:      base_rural_density = 1–8 чел/км²
Сибирская окраина:    base_rural_density = 0.1–1 чел/км²
Тундровая окраина:    base_rural_density = 0.02–0.5 чел/км²
```

Тогда логика становится чище:

```text
Регион говорит: насколько земля в целом заселена исторически и экономически.
Клетка говорит: насколько конкретное место удобно для жизни.
Освоение говорит: как эта земля используется.
Город говорит: сколько людей может жить не на земле, а за счёт еды, торговли и ремёсел.
```

## 4. Обычная клетка и городская клетка — разные вещи

Нужно разделить:

```text
обычная клетка       // сельская / природная / промысловая территория
городская клетка     // клетка, где расположен город
город                // отдельный объект, привязанный к клетке
```

Город — это не просто высокий уровень освоения.

Освоения обычной клетки:

```text
пашня
пастбища
виноградники
оливковые рощи
сады
лесной промысел
рудный промысел
каменоломня
сольный промысел
рыбацкие пристани
деревни
```

Город:

```text
городское население
рынок
ремёсла
администрация
порт
склады
стены
гарнизон
переработка сырья
торговля
```

Город должен храниться отдельно:

```text
Cell {
  id
  area_km2
  region_id
  city_id optional
  development_type
  rural_population
  rural_capacity
}
```

```text
City {
  id
  name
  cell_id

  urban_population
  urban_capacity
  city_level

  food_stock
  food_demand
  water_access
  trade_access
  housing_level
  health
  security

  worked_cells[]
}
```

Если на клетке есть город, у неё может быть сельская окраина, но городское население лучше хранить именно в `City`, а не в `Cell`.

## 5. Сельское население клетки

Сельская ёмкость клетки — это не «сколько людей обязательно живёт», а максимум, к которому население может стремиться.

Формула:

```text
rural_capacity =
  area_km2
  × region_base_rural_density
  × cell_settlement_factor
  × development_factor
  × infrastructure_factor
  × health_factor
  × security_factor
```

Где:

```text
area_km2                    // площадь клетки
region_base_rural_density    // базовая плотность региона
cell_settlement_factor       // пригодность конкретной клетки для поселений
development_factor           // тип освоения: пашня, пастбища, деревни и т.д.
infrastructure_factor        // дороги, мосты, порт, рынок рядом
health_factor                // болезни, болота, климат
security_factor              // война, разбой, порядок
```

## 6. Development factor для сельского населения

Освоение клетки сильно влияет на сельское население.

Примерные значения:

```text
нет освоения:              0.05
редкое поселение:          0.20
охотничьи угодья:          0.15
пастбища:                  0.50
деревни:                   1.00
пашня:                     1.30
плодородная пашня:         1.50
ирригационные поля:        1.80
рисовые поля:              2.20
виноградники:              0.90
оливковые рощи:            0.80
сады:                      1.10
лесной промысел:           0.40
рудный промысел:           0.60
каменоломня:               0.40
сольный промысел:          0.50
городская периферия:       2.00
```

Здесь важно:

```text
пашня и деревни увеличивают сельскую ёмкость;
рудники и лес дают рабочие места, но не создают массовую плотность;
виноградники и оливки дают богатство, но меньше массовой еды, чем зерновая пашня;
тундра и пустыня могут иметь ресурсы, но низкую сельскую плотность.
```

## 7. Пример: маленькая плодородная клетка в Галисии

Данные:

```text
area_km2 = 500
region = Галисия
region_base_rural_density = 35 чел/км²
cell_settlement_factor = 0.85    // влажные холмы, жить можно, но не идеальная равнина
development_factor = 1.20        // деревни + пашня
infrastructure_factor = 1.10     // есть дороги
health_factor = 0.95             // влажность даёт небольшой минус
security_factor = 1.00
```

Расчёт:

```text
rural_capacity =
500 × 35 × 0.85 × 1.20 × 1.10 × 0.95 × 1.00

≈ 18 600 человек
```

Вывод:

```text
Клетка маленькая, но регион плотный, земля освоена, есть деревни и дороги.
Поэтому население высокое.
```

## 8. Пример: огромная тундровая клетка в Сибири

Данные:

```text
area_km2 = 25 000
region = Сибирская окраина
region_base_rural_density = 0.3 чел/км²
cell_settlement_factor = 0.10    // тундра
development_factor = 0.30        // редкое поселение
infrastructure_factor = 0.60     // дорог нет
health_factor = 0.80             // холод, сложные условия
security_factor = 1.00
```

Расчёт:

```text
rural_capacity =
25 000 × 0.3 × 0.10 × 0.30 × 0.60 × 0.80 × 1.00

≈ 108 человек
```

Для игры можно поставить мягкий минимум:

```text
если клетка заселена:
minimum_rural_population = 300–1000
```

Но общий принцип верный:

```text
огромная площадь не делает тундру густонаселённой.
```

## 9. Полезность клетки — не один показатель

У клетки не должно быть одной общей «полезности».

Лучше считать несколько разных ценностей:

```text
food_value          // еда
economic_value      // сырьё, богатство, доход
population_value    // способность поддерживать население
trade_value         // торговля, маршруты, порт
military_value      // оборона, снабжение, крепости
strategic_value     // служебная важность для AI и геополитики
control_cost        // сложность контроля
movement_cost       // движение
```

Пример:

```text
Плодородная равнина:
food_value высокий
population_value высокий
trade_value средний
military_value низкий
control_cost низкий

Тундра с мехами:
food_value низкий
population_value низкий
economic_value средний
trade_value низкий без дороги/реки
military_value низкий/средний
control_cost высокий

Горный перевал:
food_value низкий
population_value низкий
trade_value средний
military_value высокий
strategic_value высокий
control_cost высокий
```

## 10. Производство еды

Для еды площадь важна, но только через пригодность и освоение.

Формула:

```text
food_output =
  base_food
  × area_factor
  × farmland_suitability
  × development_level_factor
  × infrastructure_factor
  × labor_factor
  × weather_factor
  × damage_factor
```

Где `area_factor` считается через корень:

```text
area_factor = clamp(sqrt(area_km2 / 1000), 0.4, 4.0)
```

Пример маленькой плодородной клетки:

```text
area_km2 = 600
area_factor = 0.77
farmland_suitability = 1.35
development_level_factor = 0.80
infrastructure_factor = 1.20
labor_factor = 1.00
weather_factor = 1.00
damage_factor = 1.00

food_output = 100 × 0.77 × 1.35 × 0.80 × 1.20
≈ 100 еды
```

Пример огромной тундры:

```text
area_km2 = 25 000
area_factor = 4.00
farmland_suitability = 0.05
development_level_factor = 0.10
infrastructure_factor = 0.60
labor_factor = 0.30
weather_factor = 0.70
damage_factor = 1.00

food_output = 100 × 4.00 × 0.05 × 0.10 × 0.60 × 0.30 × 0.70
≈ 0.25 еды
```

Вывод:

```text
Площадь помогает только там, где есть пригодность.
Если пригодность почти нулевая, огромная площадь не спасает.
```

## 11. Тундра не мусор: ресурсы считаются отдельно

Тундра может быть слабой для еды и населения, но полезной для ресурсов.

Например:

```text
меха
лес
реки
рыба
железо
медь
золото
соль
стратегическая глубина
военный буфер
```

Формула для мехов:

```text
fur_output =
  base_fur
  × area_factor
  × wildlife_factor
  × development_factor
  × infrastructure_factor
  × labor_factor
```

Пример:

```text
base_fur = 20
area_factor = 4.00
wildlife_factor = 0.90
development_factor = 0.40
infrastructure_factor = 0.60
labor_factor = 0.80

fur_output = 20 × 4.00 × 0.90 × 0.40 × 0.60 × 0.80
≈ 13.8 меха
```

То есть:

```text
еда почти нулевая;
население маленькое;
но ресурсная ценность есть.
```

## 12. Город считается отдельно от сельской клетки

Городское население не должно напрямую считаться от площади клетки.

Город может стоять на маленькой клетке, но быть крупным, если у него есть:

```text
еда из окружающих клеток;
вода;
порт;
торговля;
ремёсла;
администрация;
дороги;
безопасность.
```

Формула городской ёмкости:

```text
urban_capacity = min(
  housing_capacity,
  food_supported_population,
  water_supported_population,
  jobs_supported_population,
  health_supported_population
)
× trade_factor
× security_factor
```

То есть город ограничен самым слабым местом.

Пример:

```text
жильё позволяет:          30 000 человек
еда позволяет:            22 000 человек
вода позволяет:           40 000 человек
работа позволяет:         25 000 человек
здоровье позволяет:       20 000 человек

urban_capacity = 20 000 × trade_factor × security_factor
```

Если здоровье плохое, город не должен бесконечно расти, даже если еды много.

## 13. Связь города с окружающими клетками

Город не должен использовать все клетки вокруг сразу.

У города есть ограниченное число рабочих внешних клеток:

```text
worked_cell_slots
```

Эти слоты показывают, сколько окружающих клеток город способен реально использовать, снабжать, контролировать и включать в экономику.

Важно:

```text
городская клетка не считается одним из рабочих слотов.
```

Структура:

```text
центр: городская клетка
вокруг: до 5 рабочих внешних клеток
```

Например для Ла-Коруньи:

```text
центр: город Ла-Корунья
рабочая клетка 1: рыбацкое побережье
рабочая клетка 2: сельская земля
рабочая клетка 3: пастбища / холмы
рабочая клетка 4: заблокирована до 10 000 населения
рабочая клетка 5: заблокирована до 20 000 населения
```

## 14. Пороги населения города для открытия рабочих клеток

Базовая схема:

```text
0–999 жителей       → 1 рабочая клетка
1 000+ жителей      → 2 рабочие клетки
5 000+ жителей      → 3 рабочие клетки
10 000+ жителей     → 4 рабочие клетки
20 000+ жителей     → 5 рабочих клеток
```

Таблица:

| Население города | Доступные внешние клетки | Смысл |
|---:|---:|---|
| 0–999 | 1 | маленькое поселение использует ближайшую землю |
| 1 000+ | 2 | деревня / малый городок |
| 5 000+ | 3 | нормальный город, базовая экономика |
| 10 000+ | 4 | развитый город подключает новую территорию |
| 20 000+ | 5 | крупный региональный город использует весь ближний пояс |

Формула:

```text
worked_cell_slots = 1

if urban_population >= 1_000:  worked_cell_slots += 1
if urban_population >= 5_000:  worked_cell_slots += 1
if urban_population >= 10_000: worked_cell_slots += 1
if urban_population >= 20_000: worked_cell_slots += 1

worked_cell_slots = min(worked_cell_slots, 5)
```

## 15. Что происходит после 20 000 населения

После 20 000 не нужно бесконечно открывать новые клетки.

Иначе большие города начнут поглощать слишком много карты.

После 20 000 город должен расти не вширь, а вглубь:

| Население | Что открывается |
|---:|---|
| 20 000 | максимум 5 рабочих клеток |
| 30 000 | городская периферия |
| 50 000 | крупный рынок / портовый район |
| 75 000 | развитые ремёсла / специализация |
| 100 000 | метрополия / столица / уникальные здания |
| 150 000+ | перегрузка: болезни, жильё, снабжение, порядок |

То есть:

```text
до 20 000 город расширяет зону использования земли;
после 20 000 город улучшает переработку, торговлю, районы и управление.
```

---

## 16. Порог населения не развивает клетку автоматически

Очень важное правило:

```text
Порог населения открывает право использовать клетку.
Освоение клетки — это отдельное решение игрока.
```

Пример:

```text
Город достиг 10 000 населения.
Открылась 4-я рабочая клетка.
Игрок выбирает, что с ней делать:
- распахать землю;
- организовать пастбища;
- заложить виноградники;
- открыть лесной промысел;
- открыть рудный промысел;
- оставить дикую землю;
- развить деревни.
```

То есть:

```text
Население города = доступ к территории.
Освоение = экономический выбор.
```

## 17. Еда и рост города

Городское население создаёт спрос на еду.

```text
food_demand = urban_population × food_per_person
```

Например:

```text
urban_population = 10 000
food_per_person = 1
food_demand = 10 000 еды
```

Окружающие клетки дают еду:

```text
пашня → зерно
пастбища → мясо и молочные продукты
рыбацкое побережье → рыба
сады → фрукты / орехи
оливковые рощи → оливки, часть еды + торговый товар
```

Если еды хватает:

```text
город растёт;
миграция положительная;
порядок нормальный;
цены стабильны.
```

Если еды не хватает:

```text
рост замедляется;
цены растут;
порядок падает;
миграция становится отрицательной;
возможны голод, болезни и бунты.
```

## 18. Рабочая сила города и клеток

Город даёт часть рабочей силы, но не вся городская масса работает на полях.

У города есть:

```text
ремесленники
торговцы
администрация
строители
гарнизон
служители
портовые рабочие
```

Поэтому для внешних клеток можно считать так:

```text
city_external_labor = urban_population × external_labor_share
```

Пример:

```text
urban_population = 10 000
external_labor_share = 0.15
city_external_labor = 1 500
```

Но лучше, чтобы основная рабочая сила сельских клеток шла из самой сельской клетки:

```text
total_labor_for_cell =
  cell_rural_population × rural_labor_share
  + city_external_labor_allocated_to_cell
```

То есть:

```text
сельская клетка имеет своё сельское население;
город помогает управлением, рынком, ремеслом, инструментами и частью рабочей силы.
```

---

## 19. Как выбирать рабочие клетки города

У города может быть больше соседних клеток, чем доступных слотов.

Например, вокруг города 8 возможных соседей, но доступно только 3 слота.

Игрок должен выбрать, какие клетки подключить:

```text
1. Рыбацкое побережье
2. Плодородная пашня
3. Пастбища
```

Остальные остаются:

```text
неподключённые;
слабее дают доход;
могут быть дикими;
могут принадлежать региону, но не работать на город напрямую.
```

Позже, когда город растёт, он открывает новые слоты.

## 20. Движение юнитов

Для движения важнее не площадь клетки, а расстояние между центрами соседних клеток.

Хранить нужно не только `area_km2`, но и:

```text
distance_to_neighbor_km
```

Формула:

```text
movement_cost =
  distance_km / base_march_distance
  × terrain_modifier
  × cover_modifier
  × road_modifier
  × river_modifier
  × weather_modifier
```

Например:

```text
base_march_distance = 40 км
```

Ограничение:

```text
movement_cost = clamp(movement_cost, 0.5, 5.0)
```

Пример маленькой клетки Нидерландов:

```text
distance_km = 12
terrain = равнина
road_modifier = 0.8

movement_cost = 12 / 40 × 0.8 = 0.24
после clamp = 0.5
```

Пример большой клетки Сибири:

```text
distance_km = 130
terrain = тундра / лес
road_modifier = 1.6

movement_cost = 130 / 40 × 1.6 = 5.2
после clamp = 5.0
```

Вывод:

```text
маленькие клетки не становятся бесплатными;
огромные клетки не проходятся как маленькие;
дороги и рельеф сильно влияют на движение.
```

## 21. Контроль территории

Большие клетки должны быть сложнее контролировать.

Формула:

```text
control_cost =
  area_factor
  × remoteness_factor
  × terrain_control_modifier
  × population_modifier
  × road_modifier
  × security_modifier
```

Пример:

```text
маленькая плодородная клетка с дорогами:
area_factor = 0.7
remoteness = 1.0
terrain = 0.9
population = 0.8
road = 0.8
control_cost ≈ низкий
```

```text
огромная тундровая клетка без дорог:
area_factor = 4.0
remoteness = 1.5
terrain = 1.4
population = 1.3
road = 1.5
control_cost ≈ очень высокий
```

Большая пустая земля может давать мало дохода, но требовать много контроля.

Это важно для Сибири, степей, пустынь и гор.

## 25. Итоговая модель

```text
Регион
↓
задаёт базовую плотность населения и исторический уровень освоенности

Клетка
↓
имеет площадь, природу, пригодность, освоение, сельское население

Город
↓
имеет городское население, еду, торговлю, ремёсла, порт, управление

Порог населения города
↓
открывает больше рабочих внешних клеток

Игрок
↓
выбирает, какие клетки подключить и как их освоить

Клетки
↓
дают еду, сырьё, рабочие места, стратегические эффекты

Город
↓
перерабатывает сырьё, растёт, торгует и открывает новые возможности
```

Коротко:

```text
Площадь — масштаб.
Регион — базовая плотность.
Клетка — пригодность и сельское освоение.
Город — городское население и переработка.
Пороги населения — доступ к новым рабочим клеткам.
```

## 26. Главные правила

1. Клетка остаётся минимальной ячейкой. Внутри неё нет подклеток.
2. `habitable_share` лучше заменить на `settlement_factor` или `usable_land_factor`.
3. `base_density` хранится на уровне региона, а не отдельной клетки.
4. Площадь клетки хранится в км² и переводится в `area_factor` через квадратный корень.
5. Большая площадь усиливает потенциал, но не создаёт пригодность из ничего.
6. Маленькая плодородная клетка Европы может быть ценнее огромной тундровой клетки для еды и населения.
7. Огромная тундра может быть ценна не едой, а мехами, лесом, рудами, реками и стратегической глубиной.
8. Город — отдельный объект, а не просто тип освоения клетки.
9. Городская клетка не считается рабочей внешней клеткой.
10. Население города открывает рабочие клетки по порогам.
11. Порог населения открывает доступ к клетке, но не развивает её автоматически.
12. После 20 000 населения город лучше развивать вглубь: районы, рынок, порт, ремёсла, жильё, здоровье, порядок.
13. Движение юнитов считается по расстоянию между центрами соседних клеток, а не напрямую по площади.
14. Контроль больших пустых клеток должен быть дорогим.
15. Все тяжёлые геометрические вычисления считаются один раз и кэшируются.
