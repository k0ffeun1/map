# Методы и способы создания административного деления внутри провинции

Если говорить именно о **создании административного деления внутри уже существующей провинции** — для игры, генератора карты или GIS — методов очень много. Их удобно разделить на несколько больших семейств. Причём хороший генератор обычно использует **не один метод, а смесь 3–6 методов**.

## 1. Чисто геометрические методы

Это методы, которые смотрят только на форму провинции.

| Метод | Что получается | Реалистичность |
|---|---|---:|
| Обычный Voronoi | области вокруг точек-центров | ⭐⭐ |
| Weighted Voronoi | центры имеют разный «вес» | ⭐⭐⭐ |
| Multiplicatively Weighted Voronoi | размер зон сильно зависит от веса | ⭐⭐⭐ |
| Additively Weighted Voronoi | более мягкое управление размерами | ⭐⭐⭐ |
| Power Diagram | продвинутый взвешенный Voronoi | ⭐⭐⭐ |
| Centroidal Voronoi / Lloyd | равномерные аккуратные районы | ⭐⭐ |
| Capacity-Constrained Voronoi | заданная площадь каждой зоны | ⭐⭐⭐⭐ |
| Anisotropic Voronoi | рост в разных направлениях неодинаков | ⭐⭐⭐⭐ |
| Geodesic Voronoi | расстояние считается внутри формы провинции | ⭐⭐⭐⭐ |
| Random Voronoi + distortion | хаотичнее обычного Voronoi | ⭐⭐⭐ |
| Grid subdivision | квадратная/шестиугольная сетка | ⭐ |
| Recursive splitting | последовательное деление области | ⭐⭐⭐ |
| BSP | рекурсивное разрезание | ⭐⭐ |
| Random chord splitting | случайные линии через область | ⭐⭐ |
| Polygon cutting | разрезы полигона кривыми/линиями | ⭐⭐⭐ |
| Space-filling subdivision | заполнение пространства регионами | ⭐⭐⭐ |

Обычный Voronoi сам по себе почти всегда выглядит **слишком искусственно**.

## 2. Рост территорий от центров

Это уже намного ближе к настоящим административным границам.

Внутри провинции размещаются центры будущих районов, после чего территории постепенно растут.

### 2.1 Region Growing

Каждая клетка начинает расширяться:

```text
A A A A B B
A A A B B B
A A C C B B
D C C C C B
D D C C E E
D D D E E E
```

Но рост можно сделать неравномерным.

### 2.2 Flood Fill Growth

Распространение из нескольких seed-точек.

Каждая зона забирает соседние пиксели/ячейки.

### 2.3 Multi-source BFS

Все административные центры одновременно начинают расширение.

Ближайшая ещё свободная клетка присоединяется к соответствующему району.

### 2.4 Weighted BFS

Разным районам задаётся разная скорость.

Например:

```text
район A = 1.2
район B = 0.8
район C = 1.5
```

Поэтому территории получаются разными.

### 2.5 Priority Queue Growth / Dijkstra Growth

Один из лучших вариантов.

Для каждой клетки рассчитывается:

```text
cost = distance + shape + direction + noise + constraints
```

И зона растёт туда, где стоимость минимальна.

### 2.6 Stochastic Growth

Рост имеет случайный компонент:

```text
cost =
distance
+ random_noise
+ border_penalty
+ compactness_penalty
```

Получаются естественные выступы.

### 2.7 Competitive Growth

Районы конкурируют за клетки.

Очень хороший метод для политических границ.

### 2.8 Cellular Automata

Клетка смотрит на соседей и решает, к какому району присоединиться.

Позволяет потом «обрабатывать» границы.

## 3. Front Propagation

Очень мощная группа методов.

Представь, что из административных центров идёт **волна**.

```text
        центр A
          ↓
      → → → → →

            ← ←
              центр B
```

Когда волны сталкиваются — возникает граница.

Используются:

- Fast Marching Method;
- Fast Sweeping Method;
- Level Set;
- Wavefront propagation;
- Multi-source propagation.

Особенно хорошо работает вместе с cost map.

---

## 4. Cost-field / Cost-map division

Это один из наиболее универсальных способов.

Для всей провинции создаётся карта стоимости движения:

```text
cell_cost =
base
+ noise
+ distance
+ shape
+ directional_bias
+ border_bias
```

Затем районы распространяются по ней.

Например:

```text
нормальное направление       cost 1
нежелательное направление    cost 3
желательная территория       cost 0.6
```

Это даёт очень сильный контроль над формой.

---

## 5. Noise-based методы

Шум нужен главным образом **не для самого деления, а для разрушения идеальной геометрии**.

### Perlin Noise

Плавные крупные искажения.

### Simplex Noise

Похож на Perlin, но часто удобнее.

### OpenSimplex

Хороший вариант для генерации карт.

### Fractal Brownian Motion — FBM

Несколько уровней шума:

```text
N =
N1
+ 0.5*N2
+ 0.25*N3
+ 0.125*N4
```

Даёт крупные и мелкие отклонения одновременно.

### Value Noise

Простой вариант.

### Worley Noise

Хорош для формирования «островков влияния».

### Domain Warping

Особенно полезен.

Вместо:

```text
noise(x, y)
```

берём:

```text
noise(
 x + noise2(x,y),
 y + noise3(x,y)
)
```

Получаются сложные извилистые структуры.

### Ridged Noise

Можно создавать линейные барьеры.

### Curl Noise

Создаёт направленные потоки.

## 6. Деформация уже созданных границ

Можно сначала сделать Voronoi или growth, а потом отдельно испортить идеальные границы.

Например была граница:

```text
─────────────
```

становится:

```text
───╮
   ╰──╮
      ╰────╮
           ╰──
```

Методы:

- midpoint displacement;
- fractal displacement;
- random vertex displacement;
- spline distortion;
- Bézier distortion;
- polyline perturbation;
- domain warp;
- iterative border jitter;
- constrained border random walk.

---

## 7. Random Walk

Граница буквально строится случайным блужданием.

Например:

```text
начало
 ↓
 ↓
 ↘
 →
 ↘
 ↓
 ↙
 ↓
```

Есть разновидности:

- pure random walk;
- biased random walk;
- correlated random walk;
- constrained random walk;
- directed random walk;
- self-avoiding walk.

Чистый Random Walk плох.

Но **constrained / biased random walk** может давать очень интересные политические границы.

## 8. Графовые методы

Очень важны для сложной процедурной генерации.

Сначала территория разбивается на маленькие базовые элементы:

```text
o--o--o--o
|\ |\ |\ |
o--o--o--o
|\ |\ |\ |
o--o--o--o
```

Каждая клетка становится вершиной графа.

Затем клетки объединяются.

### Graph Partitioning

Цель:

```text
разделить граф на N связных частей
```

Существуют:

- Kernighan–Lin;
- METIS-style partitioning;
- spectral partitioning;
- min-cut;
- normalized cut;
- graph clustering;
- balanced graph partitioning;
- community detection;
- region adjacency graph partitioning.

Это уже очень серьёзный способ.

---

## 9. Mesh-based division

Провинция сначала разбивается:

- треугольниками;
- полигонами;
- hex-клетками;
- irregular mesh.

А потом эти элементы объединяются в административные районы.

Особенно удобно использовать:

### Delaunay triangulation

```text
    /\
 /\ /  \
/__\____\
\  /\   /
 \/__\_/
```

После чего треугольники группируются.

---

## 10. Supercell / Microcell aggregation

Очень хороший подход для глобальной стратегии.

Сначала вся провинция разбивается на **сотни маленьких территориальных элементов**.

Например:

```text
провинция
↓
400 микроклеток
↓
12 административных районов
```

После этого районы создаются путём объединения соседних микроклеток.

Это позволяет получать намного более естественные формы.

---

## 11. Seed placement — способы размещения центров

Даже при одном и том же алгоритме результат радикально зависит от расположения seeds.

### Completely random

Полностью случайно.

### Uniform random

Равномерно случайно.

### Poisson Disk Sampling

Очень хороший метод.

Центры не могут находиться слишком близко.

```text
•          •

      •

           •

  •
```

### Blue Noise Sampling

Похож на Poisson Disk.

### Stratified Sampling

Провинция делится на участки, и в каждом ставится центр.

### Farthest Point Sampling

Следующий центр ставится максимально далеко от остальных.

### Density Weighted Sampling

Больше центров появляется в определённых областях.

### Boundary-aware Sampling

Центры избегают краёв.

### Capital-first placement

Сначала ставится главный центр, затем остальные относительно него.

---

## 12. Hierarchical subdivision

Очень подходит именно для административного деления.

Не:

```text
провинция
↓
15 районов сразу
```

А:

```text
провинция
     ↓
  3 субрегиона
     ↓
по 3–6 районов
```

Получаются естественные группы территорий.

Можно делать сколько угодно уровней:

```text
государство
↓
провинция
↓
округ
↓
район
↓
муниципалитет
```

---

## 13. Recursive subdivision

Провинция делится на две части.

Потом каждая часть снова.

```text
       province
       /      \
      A        B
    /  \     / \
   C    D   E   F
```

Количество зон можно контролировать.

Это хорошо создаёт **исторически сложившуюся структуру**.

---

## 14. Split-and-grow

Сначала территория делится примерно:

```text
A
B
C
D
```

Затем границы начинают расти/деформироваться.

Очень хороший гибридный подход.

---

## 15. Skeleton-based subdivision

Для полигона строится внутренний skeleton.

```text
     _______
   /         \
  /    |      \
 | ----+----   |
  \    |      /
   \_________/
```

Используются:

- medial axis;
- straight skeleton;
- Voronoi skeleton.

По скелету можно создавать естественные центры и направления деления.

---

## 16. Shape-aware subdivision

Алгоритм анализирует форму самой провинции.

Например:

```text
████████
   ███
   ███
```

Он понимает, что есть:

- широкий север;
- узкий перешеек;
- южная часть.

И старается провести административную границу через узкий участок.

Полезные методы:

- polygon neck detection;
- concavity detection;
- bottleneck detection;
- medial-axis analysis;
- shape decomposition.

---

## 17. Watershed segmentation

Метод из обработки изображений.

Если создать «высотное поле»:

```text
 /\        /\
/  \______/  \
```

и запустить watershed, территория разделится по «водоразделам».

Высоты могут быть полностью искусственными.

Это позволяет получить очень органичные зоны.

---

## 18. Reaction-Diffusion

Можно использовать системы типа Gray–Scott.

Получаются органические структуры.

Для реальных административных границ напрямую используется редко, но может использоваться как дополнительное поле.

---

## 19. Potential Fields

Каждый район создаёт поле притяжения:

```text
P_i(x,y)
```

Клетка относится к району, где потенциал выше.

Потенциал можно сделать:

```text
distance
+ noise
+ weight
+ direction
+ regional_bias
```

Получается продвинутый вариант Voronoi.

---

## 20. Gravity Model

Центры имеют «массу».

Например:

```text
столица        mass 10
крупный центр  mass 5
малый центр    mass 2
```

И притягивают окружающую территорию.

Получаются крупные и маленькие административные районы.

---

## 21. Agent-based генерация

Каждая административная территория — отдельный агент.

Агенты пытаются:

- расширяться;
- сохранять компактность;
- захватывать выгодные клетки;
- избегать чужих центров;
- сохранять связь территории.

```text
A хочет расширяться →
B хочет расширяться ←

A █████│████ B
```

Очень мощный подход.

---

## 22. Simulation-based borders

Можно симулировать историческое развитие.

```text
1. появляются поселения;
2. вокруг них возникает зона влияния;
3. поселения растут;
4. некоторые поглощают соседние;
5. появляются административные центры;
6. фиксируются границы.
```

Это один из самых реалистичных, но дорогих способов.

---

## 23. Settlement-based division

Если есть города/поселения.

Каждый район формируется вокруг:

- города;
- поселения;
- административного центра.

Простейший вариант:

```text
город → Voronoi
```

Продвинутый:

```text
город
+
population
+
road accessibility
+
travel time
+
terrain
```

---

## 24. Travel-time division

Один из наиболее реалистичных методов настоящего административного деления.

Вместо расстояния:

```text
distance = километры
```

используется:

```text
distance = время пути
```

Например:

```text
до города A: 25 мин
до города B: 41 мин

→ территория A
```

---

## 25. Network-based division

Границы строятся относительно сети:

- дорог;
- рек;
- железных дорог;
- торговых путей.

Может использоваться network Voronoi.

---

## 26. River-basin subdivision

Районы создаются по бассейнам рек.

Это очень реалистичный исторический принцип.

---

## 27. Terrain-based division

Границы ориентируются на:

- горы;
- хребты;
- долины;
- реки;
- пустыни;
- болота;
- побережье.

```text
район A █████
^^^^^^^^^^^^^^ горный хребет
район B █████
```

## 28. Cultural division

При наличии культурной карты алгоритм старается:

```text
одна культура → один административный район
```

или наоборот намеренно смешивает территории.

---

## 29. Linguistic division

Аналогично языковым зонам.

---

## 30. Ethnic / demographic clusters

Административные территории формируются вокруг демографических кластеров.

---

## 31. Economic regions

Зоны создаются вокруг экономических центров.

```text
город
↓
рабочие связи
↓
рынок
↓
торговые связи
↓
административный район
```

---

## 32. Accessibility regions

Каждый район должен иметь хорошую связность со своим центром.

Можно минимизировать:

```text
sum(travel_cost(cell, capital))
```

---

## 33. Population-balanced division

Очень распространённый принцип.

```text
провинция = 1 000 000 жителей
10 районов

≈100 000 жителей / район
```

При этом площади могут быть совершенно разными.

---

## 34. Area-balanced division

Наоборот — районы имеют приблизительно одинаковую площадь.

---

## 35. Multi-objective optimization

Очень мощный метод.

Алгоритму задаются одновременно десятки требований.

```text
Score =
w1 * AreaBalance
+
w2 * Compactness
+
w3 * PopulationBalance
+
w4 * BorderQuality
+
w5 * Connectivity
+
w6 * CapitalPosition
```

Затем алгоритм ищет лучший вариант.

---

## 36. Genetic Algorithm

Одна карта = один «организм».

Создаём 100 вариантов.

Лучшие скрещиваются.

```text
generation 1
↓
generation 2
↓
generation 3
...
↓
generation 200
```

И постепенно карта улучшается.

---

## 37. Simulated Annealing

Очень хороший метод оптимизации границ.

Случайно:

```text
перебросить клетку A → B
```

Если карта стала лучше — оставить.

Иногда разрешать и ухудшение, чтобы не застрять в локальном оптимуме.

---

## 38. Hill Climbing

Постепенно передвигать границы туда, где улучшается Score.

---

## 39. Monte Carlo

Создать тысячи вариантов:

```text
map 1
map 2
map 3
...
map 10000
```

И выбрать лучший.

---

## 40. Constraint Satisfaction

Можно жёстко задавать правила.

```text
каждая зона связна
каждая зона > 300 км²
каждая зона < 1200 км²
не должно быть анклавов
центр находится внутри зоны
```

Генератор ищет решение, удовлетворяющее ограничениям.

---

## 41. Integer Programming / Mathematical Optimization

Для очень строгого деления можно использовать:

- Linear Programming;
- Integer Programming;
- Mixed Integer Programming;
- Constraint Programming.

Очень мощно, но вычислительно дорого.

---

## 42. Redistricting algorithms

Есть целая научная область автоматического создания избирательных округов.

Оттуда можно взять огромное количество алгоритмов:

- shortest splitline;
- recursive split;
- ReCom;
- Flip MCMC;
- spanning tree partition;
- balanced districting;
- compact districting.

### ReCom

Особенно интересен.

Два соседних района:

```text
A + B
```

объединяются.

Строится spanning tree.

Потом дерево разрезается снова:

```text
A' + B'
```

Через сотни итераций получаются очень естественные районы.

---

## 43. Minimum Spanning Tree subdivision

Микроклетки соединяются графом:

```text
●──●
│ /│
●──●──●
```

Строится MST.

После этого некоторые рёбра удаляются.

Получаются связанные административные регионы.

---

## 44. Spectral Clustering

Использует свойства графа и хорошо находит естественные группы клеток.

---

## 45. Region Merging

Сначала создаётся слишком много маленьких зон:

```text
50 зон
```

потом соседние постепенно объединяются:

```text
50
↓
36
↓
24
↓
15
```

Это очень хороший метод.

---

## 46. Region Splitting

Обратный подход.

Начинаем:

```text
1 большая провинция
```

и делим самый большой район:

```text
1 → 2 → 4 → 7 → 12
```

---

## 47. Split-and-Merge

Комбинация обоих подходов.

Очень хороший вариант для генерации.

---

## 48. Boundary relaxation

После генерации районы несколько раз исправляются:

```text
слишком острый выступ → убрать
маленький карман → объединить
узкий перешеек → исправить
анклав → удалить
```

---

## 49. Majority smoothing

Клетка смотрит на соседей.

Если:

```text
6 соседей = B
2 соседа = A
```

она становится B.

Очень простой способ очистки границ.

---

## 50. Morphological processing

Из обработки изображений:

- erosion;
- dilation;
- opening;
- closing.

Позволяет удалять:

- микровыступы;
- дырки;
- узкие перешейки.

---

## 51. Polygon simplification

После генерации границ:

- Douglas–Peucker;
- Visvalingam–Whyatt;
- Chaikin smoothing.

Но слишком сильное сглаживание делает границу неестественной.

---

## 52. Border segmentation

Очень полезный подход.

Граница провинции делится на несколько участков, которые закрепляются за внутренними районами.

За счёт этого внутренние зоны естественно получают выход к внешней границе.

---

## 53. Coastal frontage balancing

Для прибрежной провинции можно заставлять несколько районов получать море.

Вместо:

```text
AAAAAAAAAAAAAAAA ← весь берег одному району
BBBB CCCC DDDD
```

делать:

```text
AAA BBB CCC DDD
AAA BBB CCC DDD
```

---

## 54. Radial division

От одного центра:

```text
       \ | /
        \|/
   ------●------
        /|\
       / | \
```

Подходит для столичного региона.

Но сам по себе выглядит искусственно.

---

## 55. Corridor-based regions

Некоторые районы специально делаются вытянутыми:

```text
████████████
```

Это может имитировать:

- долины;
- побережья;
- торговые коридоры.

---

## 56. Compactness-driven regions

Районы пытаются быть округлыми.

Используются метрики:

- Polsby–Popper;
- Reock;
- perimeter/area;
- convex hull ratio.

---

## 57. Irregularity-driven regions

Можно наоборот специально требовать:

```text
низкую/среднюю компактность
```

Тогда границы становятся исторически более интересными.

---

## 58. Historical-growth simulation

Интересный вариант для глобальной стратегии.

```text
год 1000
→ 30 маленьких владений

год 1200
→ часть объединяется

год 1400
→ остаётся 12 административных единиц
```

Границы будут выглядеть намного естественнее, потому что являются результатом развития.

---

## 59. Feudal-domain simulation

Первоначально территория раздаётся нескольким центрам:

```text
баронство
баронство
графство
баронство
```

Потом владения объединяются.

Получается крайне интересная геометрия.

---

## 60. Administrative-center hierarchy

```text
региональная столица

    ↓

районные центры

    ↓

местные центры
```

И территория строится вокруг этой иерархии.

---

## 61. Template-based generation

Можно иметь реальные прототипы.

Например взять структуру:

```text
Ла-Корунья
```

и извлечь из неё характеристики:

- количество районов;
- распределение площади;
- компактность;
- количество соседей;
- длину границ;
- положение административных центров;
- отношение внутренних/приграничных зон.

После этого создавать **новые фэнтезийные территории с тем же статистическим стилем**.

Это очень сильный подход.

---

## 62. Morphological template transfer

Можно перенести структуру реального региона на другую форму.

Было:

```text
реальный регион
A B C
D E C
D F F
```

Переносим эту топологию в другую провинцию:

```text
    A A
 B B C C
 D E C
 D F F F
```

Сами координаты другие, но структура похожа.

---

## 63. Topology-first generation

Сначала вообще не рисуется карта.

Сначала создаётся граф:

```text
      A
     / \
    B---C
   / \ /
  D---E
```

То есть определяется:

> какой район с каким граничит.

А уже потом граф «укладывается» внутрь провинции.

Очень перспективный способ.

---

## 64. Geometry-first generation

Обратное:

```text
сначала территория
↓
потом анализ соседства
```

---

## 65. Topology + Geometry hybrid

Наиболее продвинутый вариант.

Сначала задаём примерно желаемую структуру:

```text
A сосед B,C
B сосед A,C,D
C сосед A,B,D,E
```

А алгоритм ищет геометрию, максимально соответствующую ей.

---

## 66. Machine Learning

Теоретически можно обучить модель на реальных административных границах.

Вход:

```text
форма провинции
количество районов
```

Выход:

```text
маска административных районов
```

Подходы:

- CNN;
- U-Net;
- diffusion model;
- graph neural networks;
- reinforcement learning.

Но для игры обычно это **излишне сложно**.

---

## 67. Procedural Grammar

Можно создать набор правил.

```text
ЕСЛИ провинция вытянута:
    делить поперёк длинной оси

ЕСЛИ есть узкий перешеек:
    провести там границу

ЕСЛИ район слишком большой:
    разделить

ЕСЛИ район слишком маленький:
    объединить
```

Получается своеобразная **грамматика административных границ**.

---

## 68. Rule-based generator

Можно иметь десятки правил:

```text
не создавать анклавы
не делать острые углы < 20°
не делать перешейки < X
не создавать районы меньше X
не создавать слишком компактные районы
не создавать абсолютно прямые границы
```

---

## 69. Hybrid procedural generation

Практически всегда лучший результат даёт:

> **не один алгоритм, а цепочка алгоритмов.**

Например:

```text
ПРОВИНЦИЯ
   ↓
анализ формы
   ↓
размещение районных центров
   ↓
Poisson Disk
   ↓
создание микроклеток
   ↓
Delaunay graph
   ↓
weighted region growth
   ↓
cost field
   ↓
competition
   ↓
boundary noise
   ↓
region balancing
   ↓
border relaxation
   ↓
удаление анклавов
   ↓
устранение узких перешейков
   ↓
polygon simplification
   ↓
ГОТОВО
```

---

# Рекомендуемая архитектура для глобальной стратегической карты

Для реалистичного ADM-2 внутри провинций лучше **не использовать обычный Voronoi как конечный метод**.

Рекомендуемая система:

```text
               PROVINCE
                   │
          Shape Analysis
                   │
        ┌──────────┴─────────┐
        │                    │
Capital anchor          Secondary seeds
        │                    │
        └─────────┬──────────┘
                  ↓
            Poisson seeds
                  ↓
          Microcell mesh
          300–1000 cells
                  ↓
          Delaunay graph
                  ↓
     Weighted competitive growth
                  ↓
             Cost field
                  ↓
       Controlled irregularity
                  ↓
          Region balancing
                  ↓
      Boundary restructuring
                  ↓
       Topology validation
                  ↓
            Final polygons
```

## Параметры формы района

```text
AREA
COMPACTNESS
ELONGATION
BORDER_ROUGHNESS
SEED_INFLUENCE
GROWTH_SPEED
DIRECTION_BIAS
NEIGHBOR_COUNT
COAST_ACCESS
PROVINCE_BORDER_ACCESS
NECK_TOLERANCE
ENCLAVE_TOLERANCE
```

Пример:

```text
район 1
area_weight       1.4
compactness       0.55
elongation        0.3
roughness         0.45

район 2
area_weight       0.7
compactness       0.8
elongation        0.15
roughness         0.25

район 3
area_weight       1.1
compactness       0.4
elongation        0.65
roughness         0.55
```

Тогда районы **не будут выглядеть как одинаковые куски одного Voronoi**.

## Главная идея

Для реалистичного административного деления лучше генерировать не сами линии границ, а **процесс, из которого эти границы возникают**.

На практике очень сильная связка:

```text
microcells
→ graph
→ competitive growth
→ optimization
→ border cleanup
```

Именно такой подход обычно выглядит намного убедительнее простого разрезания полигона.
